## 所見

- **Windows Terminal**: 食い違いは半角カナの濁点 (U+FF9E / FF9F を 1 書記素に結合する core と、独立に 1 セル進める端末) だけ。これを除けば ratatui の差分 (継続セルを skip) で 1,000 回更新後も一直線。自前差分 (CUP 明示) は出力量が約 1.45 倍で利点がない → ratatui を採る。
- **conhost**: 端末は書記素クラスタを扱わず **スカラ値ごとに幅を決める** (結合文字・ZWJ・国旗が分解される) うえ、曖昧幅の文字の幅を **フォントのグリフ幅で決める** (`─ │ ▶` は 1、`● … ↑ ↓ α Ж` と PUA は 2)。unicode-width の narrow / cjk のどちらの表とも一致せず、どちらの renderer でも崩れる。
- 以上から、conhost では core の幅の表 (曖昧幅 1/2) だけで整合させることはできない。

## 結論

1. **ratatui 0.30.2 + crossterm 0.29.0 の差分描画を採る** (継続セルを `skip` とする前提 (04 §4.2) が成り立つ)。自前差分は出力量が約 1.45 倍で利点がない。ADR-0005 の S-06 の条件は満たした。
2. **半角カナの濁点・半濁点**: 両端末で基底とは別に 1 セル進めて描く → core の幅に各 1 を足す (03 §13.2、反映済み)。
3. **conhost**: 書記素クラスタを扱わずスカラごとに幅を決める。曖昧幅はフォントのグリフ幅で決まる (`● … ↑ ↓` と PUA は 2、`─ │ ▶` は 1、`α Ж` は 2)。曖昧幅 2 を前提にしても `α Ж` と罫線が core の表と合わない。**既知の制約として許容し、eve-tui の装飾は ASCII に縮退する** (確定 (ユーザー回答)、04 §3.7 A2)。
4. **`ambiguous_width_hint` の表**: Windows Terminal → 1、conhost → 2 (04 §5.2)。
5. **記号**: `⚠ ✖ ℹ ✓ ‹ › ▶` と罫線 `─ │ ┌ ┐ └ ┘` は両端末で 1 セル (04 §3.7 に反映)。`● … ↑ ↓` は conhost で 2 セル。
