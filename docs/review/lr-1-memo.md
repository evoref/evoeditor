# LR-1 確認用のメモ: Apache-2.0 の特許条項と NOTICE の運用

**このメモは法的助言ではありません。** 条文の一般的な読みと、このリポジトリの現状の事実を整理したもので、PO (あなた) が LR-1 を「確認済み」にするか、専門家に相談するかを決めるための材料です。docs/12 §3.8 の LR-1 は **v0.1 のリリースゲート** (09 §8.2「ライセンス・名称」の行) で、リリースのチェックリストに結果を書く必要があります。

## 1. LR-1 が確かめたいこと

docs/12 §3.8: 「Apache-2.0 の特許条項と `NOTICE` の運用」。具体的には次の 2 点です。

1. **特許条項** (Apache-2.0 第 3 条): 自分 (と、将来の寄稿者) の寄稿に必然的に含まれる特許請求項を、利用者に無償で許諾することになるが、それで問題ないか。特許報復 (利用者が特許訴訟を起こすとライセンスを失う) の条項の影響。
2. **NOTICE の運用** (第 4 条): 再配布者に帰属表示を守らせる仕組みを、正しく置いて、運用できているか。

## 2. 条文の要点 (Apache License 2.0)

| 条 | 内容 (概要) | 本プロジェクトへの意味 |
|---|---|---|
| 第 2 条 | 著作権の許諾: 複製・改変・再配布・サブライセンス。ソースの公開義務は無い | 誰でも、非公開の製品や商用の製品に組み込める (docs/12 §3.3 で決定済み) |
| 第 3 条 | **特許の許諾**: 寄稿者は、自分の寄稿に必然的に含まれる自己の特許請求項について、利用者に無償・取消不能の特許ライセンスを与える。**特許報復**: このソフトウェアが特許を侵害すると主張して訴訟を起こした者は、その時点でこのソフトウェアに関する特許ライセンスを失う | 自分が特許を持っていても、このコードに必然的に含まれる範囲は利用者に許諾済みになる。他人の寄稿に含まれる特許も同様に許諾される |
| 第 4 条 | **再配布の条件**: (a) ライセンス文の写しを渡す、(b) 改変したファイルに改変の旨を表示する、(c) ソースの著作権・特許・商標・帰属の表示を残す、(d) **`NOTICE` があれば、その帰属表示を配布物に含める** | 本プロジェクトの配布物にも `LICENSE`・`NOTICE` を同梱する (済み)。派生物の配布者に `NOTICE` の保持を求める |
| 第 5 条 | 寄稿は、別段の明示がなければ、このライセンスの条件で提供されたものとみなす | inbound = outbound が条文で裏付けられる (docs/12 §3.5) |
| 第 6 条 | **商標の使用は許諾しない** (NOTICE の再現に必要な範囲を除く) | 名称・ロゴは別に守る必要がある (LR-5、v1.0 のリリース前) |
| 第 7・8 条 | 現状のまま提供、保証・責任なし | `LICENSE` のとおり |

## 4. 確認してほしい論点 (専門家に聞くなら、そのまま質問にできます)

自分で確認する場合も、各項目に「はい / いいえ / 分からない」を付けてください。

1. **権利者は誰か**: `NOTICE` と `Cargo.toml` の `authors` は `evoref` です。これは (a) あなた個人の屋号・ハンドル、(b) 法人、(c) 団体のどれですか。著作権の表示 (`Copyright 2026 evoref`) がその権利者の名前として正しいですか。
2. **勤務先などの権利**: このソフトウェアは、勤務先 (雇用契約) や委託の業務とは関係なく、あなた個人の時間と資源で開発したものですか。関係がある場合、職務著作 (著作権法 第 15 条) や職務発明 (特許法 第 35 条) の扱いで、勤務先の了解が要ることがあります。
3. **特許**: あなた (または勤務先) が、このソフトウェアに関係し得る特許を持っている、または出願する予定がありますか。ある場合、Apache-2.0 第 3 条により、このコードに必然的に含まれる範囲の特許は、利用者に無償で許諾されます。それで差し支えありませんか。
4. **特許報復の理解**: 利用者がこのソフトウェアについて特許侵害を主張して訴えると、その利用者が受けた特許ライセンスが終わります。この防御的な効果を、意図したものとして受け入れますか。
5. **NOTICE の内容**: 現在の 3 行 (製品名・著作権者・ライセンスの旨) で足りますか。第三者のソフトウェア (依存) の帰属表示は `THIRD-PARTY-NOTICES.md` に分けてあり、`NOTICE` には混ぜていません。この分け方で問題ありませんか。
6. **外部寄稿を受けたとき**: 寄稿者の特許も第 3 条で許諾されます。寄稿を取り込む前に特許について確認する運用は要りませんか (外部寄稿の受付は未開始。LR-2・LR-3 は受付開始前に確認する項目)。
7. **公開前のチェック**: `LICENSE`・`NOTICE`・`THIRD-PARTY-NOTICES.md` が、配布物のどこにあるかを README で案内していますか (現状は zip の直下に同梱され、README の冒頭にリンクがあります)。
