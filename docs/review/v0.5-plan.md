# v0.5 の計画の材料 (2026-11-20)

v0.4.0 (2026-11-19) のリリースの直後に、v0.5 (実用化 (1) 編集と検索の拡張) の着手の準備として、範囲の各項目について **仕様が実装に入れる詳しさか** と **コードの今の状態** を 3 つの領域 (ワークスペース / 画面と編集モデル / 小さな機能と持ち越し) で点検した。その結果と、v0.5 のマイルストーン (M28〜M35) の案を、作業の材料としてまとめる。**正本ではない** (範囲と順序の正本は [08 §2.6](../08-roadmap.md#26-v05-実用化-1-編集と検索の拡張)、OQ の状態は 10)。

- 対象: `develop` の v0.4.0 の後 (コミット `bcc03ab`) の時点の仕様とコード。行番号はこの時点のもの。
- 「確認」の列: **主** = 主のセッションが該当の行を開いて確かめた。**報** = 点検した側が確かめたと報告し、主は未確認。**推** = 推測 (実測や試作をしていない)。着手の前に、報・推の行は該当の行を開いて確かめる。点検した側の報告のうち、#565 (11-15 の夜間の失敗) を「直っていない」としたものは誤りだった (#567 で直してあり、夜間の最小の反例は eve-encoding の固定の試験にある。主が確かめて #565 を閉じた)。
- 工数は 08 と同じ「週 (フルタイム換算、1 人 + AI 支援)」。大きさの目安: S = 2 日まで、M = 1 週まで、L = 2〜3 週。v0.2〜v0.4 の実績では、暦日は見立てよりずっと短い。暦日の下限は、着手前のスパイク・OS ごとの手での確認 (WSL・ネットワーク FS・Windows の ACL)・判定の夜間 fuzz の観測 (v0.5.0 から 7 日、09 §8.2) で決まる。
- v0.4 と同じく、機能は **仕様の PR (`spec/`) を先に入れてから** 実装の PR (`feat/`) を出す (ADR-0001)。振る舞いを変える修正は `fix/`、振る舞いを変えない整理は `refactor` の PR に分ける。

### 1.2 範囲と方式の扱い (点検で出た論点。推奨案)

**反映済み (M28 の決定の同期の PR、`spec/m28-v05-decisions-sync`)**: 走査・照合・横断検索は 03 §12.7・02 §13.5・06 X10、ファイル監視は 05 §12.2・02 §13.7・01 FR-117 / §4.6、FR-705 は 01 FR-705・07 §12 の「版」・02 §15。

| 論点 | 採った案 | 退けた案と理由 |
|---|---|---|
| ワークスペースの走査と除外の照合 | **自作する**: `FileSystem::read_dir` を足し、`bg` のジョブで走査する (ディレクトリをいくつか処理するごとに積み直して譲る)。gitignore の照合は eve-core の純粋関数 (06 X10 の方式) で、git との差分試験と fuzz を付ける。照合の範囲は ripgrep の既定に揃える (`.git` があるときだけ効かせ、入れ子の `.gitignore` と `.git/info/exclude` を読む。グローバルの excludesFile は読まない)。項目の数に上限を置く (案: 20 万) | `ignore` を使う案: `std::fs` を直接呼ぶので FileSystem Port と `MemFs` の試験を通らない。`WalkParallel` は自前でスレッドを作り ADR-0006 の固定 2 本に反する (WS-02) |
| 横断検索の照合 | **grep-searcher を使わない**。ファイルごとに eve-encoding で判定・復号し、eve-core の `Matcher` で探す (Shift_JIS / EUC-JP のファイル、CP932 互換文字の同一視、`\n` の扱いがエディタ内の検索と同じ結果になる)。`max_file_size` を超えるファイルとバイナリは飛ばす。03 §12.7 を 06 X10 の方式に書き直す (WS-01) | grep-searcher: UTF-8 と BOM 付き UTF-16 だけを扱い、日本語のレガシーのファイルで当たらない。速さより正しさを採る (v0.4 からの主題) |
| ファジー照合 | **自作する** (パレットの採点の規則を、パス用に詰めた形で作り直す)。`bg` のジョブで照らし、新しい入力で前のジョブを取り消し、上位 N 件だけを返す | nucleo: MPL-2.0 で許可リストに無く、rayon と parking_lot を連れてくる (推)。メインスレッドで照らす案: 10 万件で NFR-103 を割る恐れ |
| ファイル監視 | **notify を使い、debouncer の crate は使わない** (待ち合わせは Host の待機の期限で自前に行う。一定の間隔で起きるスレッドを持たない、NFR-204)。監視のイベントで **モーダルの確認を出さない** (印とメッセージだけ。確認はフォーカス復帰・切替・保存の既存の流れ)。`FsKind::Network` と WSL の DrvFs は監視せず縮退する。`links` (C) を持たないことを M29 のスパイクで確かめる | notify-debouncer-mini / full: 定期の起床がある (推) |
| 複数ペインの土台 | 分割の前に **「1 Window = 1 View」の前提を外す** 作業 (FND) を独立の PR にする (見た目は変えない。1 ペインのゴールデンは変わらない)。葉 (ペイン) ごとに `DocumentId → ViewId` を持つ。`buffer.close` は表示していた全ペインを、各ペインの最近使った順の次の文書に替える。`pane.close` は文書を閉じない | 分割と同じ PR で入れる案: 境界の型・TUI・マウス・ASCII を一度に変え、レビューで追えない |
| 境界の型 (eve-view) | 追加だけで足りる見込み (`CONTRACT_VERSION` は 0 のまま、C2 の段階)。候補: `Frame.dividers` (区切りの矩形を core が確保)、`Frame.tab_line` (`TabLineModel`)、編集面の外のマウスの入力 (`InputEvent` の変種)。**タブライン・区切り・パネルを 1 つの仕様の PR (M30) で設計し**、仕様との整合・利用者・保守性の視点のレビューに掛ける | TUI が矩形の隙間から区切りを推して描く案: ヘッドレスとの食い違いとヒット判定の重複 |
| ワークスペース設定 (FR-705) の範囲 | **§1.3 の (2)**: 推奨は、v0.5 では安全な項目の適用・所有者の検査・`.editorconfig` だけを入れ、準安全・危険な項目は保留して診断を出す。信頼の記録・確認ダイアログ・`--trust`・`[!]` の表示は、最初の危険な項目 (FR-709 / 710 か v1.L の LSP) と一緒に入れる | 全部入れる案: v0.5 に信頼して有効にする危険な項目が無く、確かめようの無い UI を先に固める |

| MSRV | 1.99 に上げる (08 §2.6。PO の決定 2026-11-20)。**最初の `feat` (M29 の FR-604) が入った直後** の chore の PR で上げる | — |

### 5.4 反対の論点

- **ワークスペースの照合を自作すると、正しさ・速さで ripgrep / nucleo に劣る恐れがある**。→ git との差分試験と BM で確かめ、未達なら 02 §13.0 の手順で `ignore` (の照合の部分) を再評価する。nucleo は MPL-2.0 の承認が要る。
- **Shift_JIS のファイルを横断検索で探すには、ファイルごとに判定と復号が要り、ripgrep より遅い**。→ 日本語のレガシー資産は v0.4 からの主題なので、速さより正しさを採る。
- **カバレッジを夜間だけで見ると、低下が develop に入ってから分かる**。自己マージの運用では毎 PR のゲートだけが止める手段。→ §1.3 の (5) で PO が推奨案 (夜間と判定でゲート) に決めた。夜間の起票で翌日には分かる。
- **標準入力の (a) を残す**: `journalctl -f | evoeditor -` で SSH が切れるのは現実にあり得る。P1 からは直すべきだという見方もある。→ §1.3 の (4)。
- **FR-119 (バックアップ) は 2 度目の先送り**。データの保全の機能を送り続けることになる。→ 保存時の履歴は Undo に残る。保存の経路を FR-216 と同じ版で 2 回レビューに掛けない。
- **長大行の折り返しの試作は、送るほど基点から離れる**。→ 分割の後に作り直す前提にする。
- **FR-705 の信頼の UI を送ると、08 §2.6 の「信頼の仕組み」を v0.5 で満たさない**。→ §1.3 の (2)。
- **タブライン (Should) を送る案**: バッファ一覧とステータスの `(2/3)` で代わりになる。→ 境界の型を区切り・パネルと一緒に設計すれば追加の費用は小さく、08 §2.6 の目的に名指しで入っているので送らない。
- **工数の見立ては過大の見込み**。ただし、所有者の検査・監視・走査は OS ごとの差が大きく、手での確認が暦日の下限を決める。
