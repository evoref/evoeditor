# 性能の記録 — 開発機 (v0.5 の M32 の段 4: 対応括弧の BM-103b-bracket)

v0.5 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。**基準機の値ではない** (参考値)。リリースゲートの判定 (NFR-103: p50 2 ms / p99 8 ms、09 §5.2 の BM-103b-bracket) は、RC で基準機で測り直した値で行う。

- 環境: 開発機 (基準機ではない。Windows 11、性能の違う 2 種類のコアを持つ CPU)。端末は ConPTY (`bm_pty`)
- コミット: M32 の段 4 (`feat/eve-core-bracket-match`、PR #622) のレビューの修正 (`59fe523`) の作業ツリー
- コマンド: `cargo bench -p evoeditor --features bench-trace --bench bm_pty -- --only 103bk,103bkj --runs 1000`
- 場面:
  - BM-103b-bracket: 10 MB の文書の末尾にある、対応の無い `)` の直前への入力 (対応を 1 MiB の窓の全体まで探す)
  - BM-103b-bracket-ja: 10 MB の日本語の本文 (`、` `。` `　` が多い。全角の括弧と同じ先頭 2 バイト `E3 80` を持つ) の末尾にある、対応の無い `」` の直前への入力

| ID | n | p50 (ms) | p99 (ms) | p99.9 (ms) | 最大 (ms) |
|---|---|---|---|---|---|
| BM-103b-bracket | 1000 | 0.99 | 3.31 | 3.97 | 4.20 |
| BM-103b-bracket-ja | 1000 | 1.50 | 3.99 | 4.91 | 5.01 |

判定 (参考): どちらも開発機では NFR-103 の p50 2 ms / p99 8 ms を満たす。日本語の場面は、`、` `。` `　` で 3 バイト目を照合する分だけ p50 が約 0.5 ms 増える。

参考: 修正の前のコミット (`ad5598f`) では、同じ回に測った BM-103b が p50 0.77 / p99 2.65 ms、BM-103b-bracket が p50 0.99 / p99 2.94 ms だった。
