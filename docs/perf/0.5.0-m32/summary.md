# 性能の記録 — 開発機 (v0.5 の M32 の段 3: 複数カーソルの BM-211)

v0.5 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。**基準機の値ではない** (参考値、合否なし)。カーソルの数の上限 (`MAX_CURSORS` = 10,000、03 §4.5.1 の MCUR-6) を見直すかどうかの目安 (03 §4.7.1 の「計測」: BM-211-10k の p99 が 50 ms を超えたら仕様を先に直して見直す) に使う。RC で基準機で測り直す。

## BM-211 (複数カーソルの入力の core 区間)

- 環境: 開発機 (基準機ではない。Windows 11、性能の違う 2 種類のコアを持つ CPU)。ヘッドレス (`eve-testkit` の `Harness`、`bench` のプロファイル)
- コミット: `develop` の `5a4d55d` に、M32 の段 3 (`feat/eve-core-multi-cursor-commands`、PR #620) の 1 つ目のコミット `5cc3977` と同じ内容を足した作業ツリー。レビューの修正 (`910dc29`。入力の経路は変えていない) の前の値
- 測った日時: 2026-11-23 00:50 JST ごろ (2 ラウンドを続けて測った)
- コマンド: `cargo bench -p eve-testkit --bench bm_211` (1 回目)、`cargo bench -p eve-testkit --bench bm_211 -- --json` (2 回目)
- 条件:
  - 端末 120×40、1 MB の日本語混在のコーパス (BM-103a と同じ)
  - 先頭から 1,000 行 / 10,000 行の行頭にカーソル (主は先頭の行)
  - `InputEvent::Text("a")` → Frame の生成完了を 1,000 回 (先頭 100 回はウォームアップとして除く)
  - 各回の後に、測らずに `Backspace` で入れた文字を消す

| ID | カーソル | ラウンド | p50 (ms) | p99 (ms) | 最大 (ms) |
|---|---|---|---|---|---|
| BM-211-1k | 1,000 | 1 | 1.76 | 4.32 | 5.22 |
| BM-211-1k | 1,000 | 2 | 1.76 | 2.09 | 4.39 |
| BM-211-10k | 10,000 | 1 | 26.9 | 42.7 | 44.1 |
| BM-211-10k | 10,000 | 2 | 29.0 | 44.3 | 47.4 |

判定: `10k` の p99 (42.7 / 44.3 ms) は 50 ms を超えないので、上限 (10,000) は変えない (03 §4.7.1)。50 ms に近いので、RC で基準機で測り直し、超えたら仕様を先に直して見直す。
