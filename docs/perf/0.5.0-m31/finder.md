# 性能の記録 — 開発機 (v0.5 の M31 の段 6: ファインダの BM-125 / BM-103b-finder)

v0.5 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。**基準機の値ではない** (参考値)。リリースゲートの判定 (BM-125 p99 ≤ 50 ms、BM-103b-finder p50 2 ms / p99 8 ms。01 FR-125 AC-2、NFR-103) は、RC で基準機で測り直した値で行う。

- コミット: `develop` の `871eac3` に、M31 の段 6 (`feat/eve-core-finder`、PR #614) の 1 つ目のコミット `f78db79` を足したもの。レビューの修正 (`28858d2`。語ごとにファイル名の中で先に当てるので、一致した候補につき当てる回数が 1 回増える) の前の値で、RC で測り直す
- 環境: 開発機 (基準機ではない。Windows 11、性能の違う 2 種類のコアを持つ CPU、内蔵の NVMe SSD)。端末は ConPTY (`bm_pty`)
- コマンド: `cargo bench -p evoeditor --features bench-trace --bench bm_pty -- --only 125 --workspace-tree <木> --runs 1000` を 2 回続けて測った
- 木: `cargo xtask gen-corpus --workspace large --seed 42` (ファイル 156,841。照合の後に残る候補 91,428)。内蔵の SSD の NTFS に置いた
- 手順: 木を `DIR` で開き (ファインダが開く)、走査を終えてから、入力欄に場面の語を入れ、打鍵と BackSpace を 30 ms ごとに交互に 1,100 回 (ウォームアップ 100 回を除く 1,000 回) 打つ
  - `many`: 空の入力欄に `e` (91,428 件 → 91,322 件。一致の多い語)
  - `few`: `flat/case1234` に `5` (33 件 → 1 件。一致の少ない語)
- 区間:
  - BM-125: 打鍵の読取完了 → その入力の件数が件数の欄に出た Frame の `write` (区間の記録 `search.first_match` の一覧の版。終点の件数は、別のプロセスで先に読んで、打鍵の前後で違うことを確かめた)
  - BM-103b-finder: 同じ打鍵の `input.to_flush` (入力の読取完了 → 入力欄を反映した描画の `write`)

## 所見

- 開発機の値は、どの場面も目標の内 (BM-125 の p99 は最大 17.9 ms で目標 50 ms の約 1/3。BM-103b-finder の p99 は 1.7 ms 以下)。
- 30 ms のうちに結果が描かれずに記録が残らなかった打鍵は 0 件 (送った打鍵の数と記録の数が一致。09 §5.2 の BM-125 の判定の条件)。
- `many` は 9 万件のほとんどが一致し、全件の採点と上位 100 件の選択が走る。`few` は文字の集合による速い棄却で、多くの候補が採点の前に落ちるので約半分の時間で済む。
- 打鍵の判定区間 (BM-103b-finder) は、照合が `bg` で走るので照合の件数に依らず約 1 ms。
- 結果の JSON は保存していない (基準機の RC の計測で `--json` を付けて記録する)。
