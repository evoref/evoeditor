## 測った条件 (2026-11-26、手で追記)

- 判定コミット `4327f18` (v0.5.0-rc.1 の版上げの後の `develop` の先頭)。作業ツリーは USB 接続の外付け SSD の上なので、exe (`CARGO_TARGET_DIR`) は内蔵 NVMe SSD の NTFS の上に置いた (09 §5.3 (e))。計測データは `TEMP` (内蔵 SSD) の下にベンチが作る。ワークスペースの木は `cargo xtask gen-corpus --workspace large --seed 42` で内蔵 SSD に作った (ファイル 156,841・ディレクトリ 10,112。除外の後のファインダの候補 91,428)。

- **ツールチェーンは Rust 1.99.1** (MSRV。v0.4.0-rc.1 の記録と同じ 1.99 系)。この機械の stable (1.100.0) では一式が BM-120 で止まる: 1.100 の cargo はベンチの実行ファイルを `target\release\build\evoeditor/<hash>\out\` に置き、パスに `/` が混じる。BM-120 はこのパスをパイプの書き手として `cmd /d /c` に渡すので、cmd が `/` 以降をスイッチと読んで起動できない (計測の道具の不具合。製品のコードは関係しない。昇格の後に直す)。配布物は stable でビルドされる (`release.yml`)。

## 所見

1. **BM-102a (起動 (a)、1 MB のファイルあり) は v0.3.0 の水準に戻らない (+17.6%、約 +1.5 ms)**。08 §2.6 の (c) の条件 (v0.3.0 のコードと交互に測って p50 の差が +10% 以内) を満たさない。目標 (NFR-102 の p50 25 / p99 50 ms) には十分な余裕があり、合否には効かない。
   - M29 の直し (#598、同梱の言語の表を静的な表にした) は効いている: #598 の時点では v0.3.0 との比 0.96 (3 組)。その後の M30〜M33 で少しずつ増えた。v0.3.0 と交互に測った比 (各 3 組): #600・#601 は約 1.0、#611 (M31 の段 5、同じファイルを識別と canonical のパスで判定する) は 1.08 (約 +0.7 ms)、#628 (M33 の段 3) は 1.10〜1.17、判定コミットは約 1.18。1 つのコミットの段差ではない。
   - プロセスの中の「開く」(`bm_instr --time open_1m`、MemFs) は #598 の 2.45 ms から判定コミットの 2.73 ms へ約 +0.3 ms で、同じく M30〜M33 にかけて少しずつ増えた。残りの約 1.2 ms は MemFs に出ない部分 (実 FS への問い合わせ・OS の監視の登録など) にある見込み: 増えた区間は M31 のルートの検出と同じファイルの判定 (#608〜#611) と、M33 のファイル監視の土台 (#627) の前後。内訳は区間の記録を足して切り分ける (昇格の後の Issue)。
   - 扱い (PO の判断 2026-11-26): この所見で通し、08 §7 に繰り越しを記録して v0.6 で切り分けて直す (08 §2.6 の (c) の「戻らなければ理由を所見に書き、08 §7 に繰り越しを記録する」)。
   - 一式の値 (BM-102a 10.09 ms・BM-102b 43.70 ms) と v0.4.0-rc.1 の記録 (6.50・25.79 ms) の差の大半は、機械の状態の差 (上の「測った条件」)。
2. **自動の判定の「不合格」2 行は、機械が遅い状態のときの値**: BM-103b-search-multiline (p50 2.32 ms) と BM-103b-bracket-ja (p50 2.05 ms) は、一式の後に v0.4.0 と交互に 3 ラウンド測り直すと、それぞれ p50 1.61 ms (v0.4.0 は 1.59〜1.61 ms で差なし) と 1.49〜1.52 ms。p99 は 2.91〜3.03 ms と 3.88〜4.04 ms。目標 (p50 2 / p99 8 ms) の内と判定する。
3. **v0.5 の Must の BM はすべて目標の内**: BM-125 (p99 17.52 / 6.94 ms、目標 50 ms)、BM-103b-finder・BM-103b-search-ws (p99 1.04〜1.42 ms)、BM-204w (0.00 %)。BM-125 は送った打鍵 1,000 のすべてに記録があり、判定に使える。
4. **BM-211-10k (参考) は p99 75.5 ms で、上限 (10,000 カーソル) を見直す目安 (p99 50 ms) を超えた**。1 万カーソルで 1 文字を打つ core の区間。判定の条件ではない。上限の見直しは v0.6 の候補として 08 §7 に書く。
5. **測っていないもの**: 09 §8.2 の v0.5 の「性能」の行の、横断検索を走らせている間の BM-117w (計測のコードに場面が無い)、BM-204w の参考の起床の回数 (Windows の性能カウンタ・Linux の `strace -c`)。どちらも参考値。昇格の後に計測のコードに足す。
6. **exe の大きさ (BM-205)** は 6,323,200 → 8,624,640 バイト (+36%)。v0.5 の機能 (ペイン・ワークスペース・監視 (`notify`)・言語定義・`.editorconfig` など) の分。目安の条件は無い。
