## 所見 (2026-11-03、手で追記)

- **計測の手順の修正**: `BM-104p` (開く → 進捗) は、v0.2 の複数の文書では開いている文書を開き直すと切り替えになり読み込まない (2 回目以降は記録が 0 件になり、ベンチが止まる)。読み込むたびに `Ctrl+W` で閉じてから次を開くようにベンチ (`bins/evoeditor/benches/bm_pty.rs`) だけを直して測った。製品のコードは判定コミット `ced9f04` のまま (ベンチは配布する実行ファイルに入らない)。ベンチの修正は判定の後に `develop` へ入れる。
- **BM-101b (不合格、例外 1 件)**: p50 23.69 ms (v0.1.0-rc.1 は 34.54 ms) に対して、p99 218.57 ms が目標 (80 ms) を超えた。約 5% の回だけが約 +200 ms 遅れ、遅れは計測側 (親) の CreateProcess の中にある (BM-101a の main 入口 → 最初の Frame は遅い回も約 3 ms)。切り分け:
  - 同じベンチで起動する実行ファイルだけを入れ替えると、v0.1.0 の実行ファイルでは出ず (p99 27 ms)、v0.2 の実行ファイルで出る (p99 228 ms)。
  - ウイルス対策を一時的に止めても変わらない (p99 228 ms)。ウイルス対策が原因ではない。
  - 回と回の間を 500 ms 空けると出ない (p99 43 ms)。前の回のプロセスの終了と重なったときだけ起きる。
  - ログオフ・シャットダウンを受ける **非表示のトップレベルウィンドウ** (v0.2、05 §11.2) を作らないようにすると出ない (p99 49 ms)。原因はこのウィンドウ。
  - 利用者への影響: 前の evoeditor の終了直後 (約 0.5 秒以内) に続けて起動したときだけ、起動が約 0.2 秒遅れることがある。単独の起動は遅れない。
  - 扱い (PO 判断、2026-11-03): rc.1 は例外として判定を続け、v0.2.0 の前に `fix/` の PR で直して基準機で測り直す。
- **BM-103b-clip100**: 上の表の p50 2.07 ms は目標 (2 ms) をわずかに超えたが、同じ日に `--only 205 --runs 1000` で 2 回測り直すと p50 1.31 ms / 1.52 ms (p99 3.02 / 3.50 ms) で合格。ばらつきとして合格に読み替える。
- **前の版との比較**: BM-103b の p50 は 1.05 → 1.71 ms、p99 は 2.68 → 3.78 ms と増えたが、目標 (p50 2 ms / p99 8 ms) の内。BM-205 (exe の大きさ) は 2,713,600 → 4,953,600 バイト。
