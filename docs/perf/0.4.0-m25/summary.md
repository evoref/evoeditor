# 性能の記録 — ENV-W1 (v0.4 の M25 の 3: 先行表示の BM-104v)

v0.4 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。リリースゲートの判定は `docs/perf/0.4.0/` に測り直した値で行う。

- コミット: `9a79244` (`develop` の先頭) に、M25 の 3 の変更 (計測用ビルドの区間の記録 `open.content` / `open.partial` と、`bm_pty` の BM-104v) を足した作業ツリー。製品の振る舞いのコードは `9a79244` のまま (区間の記録は計測用ビルドの feature `bench-trace` だけにある)
- 環境 ID: `ENV-W1` (構成は `docs/perf/environments.md`)
- 判定の基準: 01 FR-122 AC-2 (09 §5.2 の BM-104v): 30 回の **p50 ≤ 300 ms** (最大値は参考)
- コマンド: `cargo bench -p evoeditor --features bench-trace --bench bm_pty -- --only 104v --runs 1000 --json` (`--runs 1000` は動作確認用の回数でないことを示すだけ。BM-104v は 1 組でウォームアップ 3 回 + 30 回)
- 区間: `Ctrl+O` → パス → `Enter` の、`Enter` の読取完了 → 文書の先頭部分を含む最初の Frame の `write` (区間の記録 `open.content`)。先行表示の先頭だった回は印 `open.partial` で数える。2 つのファイルを交互に開き、読み終えてから閉じる。始点はコマンドの受付 (01 §3.0.1) より早い入力の読取完了なので、値は受付からの区間より少し大きく出る

## 測った条件

- 6 組を続けて測った (約 10 分)。各ラウンド (JSON と文の 2 組) の前に、全体の CPU の使用率を 1 秒ごとに 5 回見た: 0.7〜7.7 % / 2.2〜8.9 % / 1.6〜5.1 %。計測の間は cargo のビルド・試験を走らせていない (エディタとブラウザは開いたまま)。
- 電源に接続。Defender のリアルタイム保護は無効 (環境の登録どおり)。
- 測る exe (`CARGO_TARGET_DIR`) と計測データ (`TEMP` の下に `bm_pty` が作る 100 MB × 4 ファイル) は内蔵 NVMe SSD (NTFS) の上 (09 §5.3 (b) / (e))。リポジトリは USB 接続の外付け SSD の上だが、計測の区間には入らない。
- 端末は `bm_pty` の ConPTY (120 × 40)。Rust 1.99.0、`bench` プロファイル (release + debuginfo)。
- ウォームキャッシュ: 各組の最初の 3 回 (ウォームアップ) でファイルを OS のキャッシュに載せる。

## 所見

- **FR-122 AC-2 は満たす**: p50 は UTF-8 168 ms、Shift_JIS 206 ms で、目標 300 ms に対して約 94 ms 以上の余裕がある。最大値も 211 ms。
- **Shift_JIS** は全読込が約 420 ms (`docs/perf/0.3.0/` の BM-104-100m-sjis p50 416 ms) なので、全回が先行表示の先頭の Frame。値はほぼ「先行表示を出す条件の 200 ms (03 §9.2.1 の `PARTIAL_AFTER`) + その後の最初のチャンクの区切り + 先頭の木の構築と Frame」で、揺れは小さい (6 組の p50 の幅 1 ms)。300 ms との差 (約 94 ms) は、200 ms の起点 (`open_read` の開始) までの経路と、先頭を送ってから描くまでに使える分。
- **UTF-8** は全読込が 200 ms の前後 (0.3.0 の BM-104-100m p50 180 ms) なので、多くの回 (79 %) は全文の Frame、読込が 200 ms を超えた回 (21 %) は先行表示の先頭の Frame (約 204〜208 ms) になる。そのため値は約 208 ms で頭打ちになり、p50 は全読込の時間の揺れ (組 1 (文) は 192.56 ms で先行表示 11 回) に従って動く。03 §9.2.1 の「UTF-8 の 100 MB では多くの場合に出さない」のとおり。
- UTF-8 の各組で、ウォームアップの後の最初の 2 回は約 110 ms で、3 回目以降 (約 160 ms〜) より速い (Shift_JIS では見えない)。100 MB の文書を閉じた後の開き直しの費用の違いと見るが、原因は調べていない (判定には影響しない)。
