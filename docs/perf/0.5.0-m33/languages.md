# 性能の記録 — 開発機 (v0.5 の M33 の段 2: 言語定義の BM-101a / BM-102a)

v0.5 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。**基準機の値ではない** (参考値)。07 §12.6.2 の段 2 の完了の条件「BM-101a / BM-102a が劣化しない」は、言語定義を書かない設定 (v0.4 で書けた設定) についての条件で、`languages/` に定義を置いた場面 (`-lang`) は参考値 (07 §12.6.1、PO の決定 2026-11-23: 起動時に `languages/` を開くジョブより前に読む)。RC で基準機で測り直す。

- 環境: 開発機 (基準機ではない。Windows 11、性能の違う 2 種類のコアを持つ CPU)。端末は ConPTY (`bm_pty`)
- コミット: M33 の段 2 (`feat/eve-config-language-definitions`、PR #625) の `bed72b7` (正規表現を組むジョブを開くジョブの後ろへ移した後) の作業ツリー。基準は `380221f` (M33 の段 1) を `git archive` で取り出してビルドしたもの
- コマンド: `cargo bench -p evoeditor --features bench-trace --bench bm_pty -- --only 101,102,101g,102g --runs 300` (`-lang` の組は 200 回)
- 注意: 同じ機械でほかのビルドと試験が走る時間帯があり、ばらつきが大きい。同じ時間帯に基準とこの PR を続けて測った組で比べる

## 言語定義を書かない起動 (判定の対象)

| ID | 組 | 基準 p50 / p99 (ms) | この PR p50 / p99 (ms) |
|---|---|---|---|
| BM-101a | 静かな時間帯 | 2.19 / 2.92 | 2.26 / 3.09 |
| BM-102a | 静かな時間帯 | 5.50 / 7.02 | 5.54 / 7.09 |
| BM-101a | 最後の組 | 2.74 / 3.83 | 2.83 / 3.82 |
| BM-102a | 最後の組 | 7.22 / 8.60 | 7.26 / 8.82 |

差はばらつきの内に収まる。

## `languages/` に 20 ファイルを置いた起動 (参考値)

| ID | p50 / p99 (ms) | 同じ回の設定なしの p50 (ms) | 増分の中央値 (ms) |
|---|---|---|---|
| BM-101a-lang | 3.04 / 4.28 | 2.78 | +0.24 |
| BM-102a-lang | 10.74 / 15.89 | 7.61 | +3.26 |

- 増分には、`config.toml` と条件付きセクションの読込の費用も混ざる (比べたのは設定なしの起動)。`languages/` の有無だけを変えた計測はしていない
- NFR-102 の目標 (p50 25 ms / p99 50 ms) の内
- 最初の実装では BM-102a が +1〜1.8 ms、BM-102a-lang が +10 ms だった。正規表現を組む作業を `PrecompileLanguages` のジョブへ移し、行頭に要る文字列 (`#!`) で始まらない行には正規表現を当てず、`languages/` の列挙で大きさが分かれば項目ごとの stat をしないようにして、上の値になった
