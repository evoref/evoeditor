# 性能の記録 — 開発機 (v0.5 の M33 の段 8: ファイル監視の BM-204w / BM-117w)

v0.5 のリリースゲートの前の、マイルストーンの作業の記録 (docs/09 §5.3)。**基準機の値ではない** (参考値)。07 §12.6.2 の段 8 の完了の条件「BM-204w (判定)・BM-117w (参考)」の手元の値で、判定は RC で基準機で測り直す。

- 環境: 開発機 (基準機ではない。Windows 11、NTFS のローカルの一時フォルダ)。端末は ConPTY (`bm_pty`)
- コミット: M33 の段 8 (`feat/eve-core-file-watch`) の作業ツリー (計測用ビルドではない `cargo bench` のビルド)
- コマンド: `cargo bench -p evoeditor --bench bm_pty -- --only 204,204w,117w --runs 1000`
- 注意: 同じ機械でほかのビルドと試験が走っている時間帯に測った

## アイドルの CPU 使用率 (判定の対象。NFR-204 AC-1・FR-117 AC-10、目標 0.1 % 未満)

| ID | 場面 | 値 |
|---|---|---|
| BM-204 | 監視なし (無題の文書)。最初の Frame の 10 秒後から 60 秒間 | 0.0000 % |
| BM-204w | 別々のディレクトリの 10 個のファイルを開いて監視している。同じ区間 | 0.0000 % |

- 値は `Get-Process` の `TotalProcessorTime` の差 (分解能は約 15.6 ms) で、60 秒間に 1 刻みも増えなかった
- Windows の監視のスレッドの起床の回数 (09 §5.2 の BM-204w の行の参考の記録) と Linux の `strace -c` は測っていない (RC で測る)

## 監視の知らせの遅れ (参考。BM-117w)

| ID | 場面 | n | p50 / p99 / 最大 (ms) |
|---|---|---|---|
| BM-117w | 10 個のファイル (別々のディレクトリ) を開き、表示していない文書のファイルを外部で書いてから、その文書の外部変更の知らせのメッセージ行が端末の画面に出るまで | 30 | 116.18 / 118.67 / 118.67 |

- 待ち合わせの 100 ms (`WATCH_SETTLE`) を含む。差の約 16 ms が、notify の知らせ・照合のジョブ・描画・ConPTY の合計
- 終点は区間の記録 (`bench-trace`) ではなく端末の画面 (メッセージ行と印は同じ照合の結果で同じ Frame に出る)。09 §5.2 の BM-117w の行の「横断検索を走らせている間」の場面は測っていない (10 万ファイルの木が要る。RC の計測で足す)
