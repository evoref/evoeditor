# 基準環境の登録

性能の記録 (`docs/perf/<版>/`) に書く **環境 ID** と、その一般化した構成 (docs/01 §3.0 と同じ粒度)。機種名・CPU や SSD の型番・容量・OS のビルド番号・ウイルス対策ソフトの製品名・電源プランの名前などの詳細は、**リポジトリの外の非公開のメモ** に書く (docs/09 §5.3、docs/11 §9.7)。

| 環境 ID | 用途 | OS の系列 | CPU | メモリ | ストレージ | 端末 | シェル | ウイルス対策 | Rust |
|---|---|---|---|---|---|---|---|---|---|
| `ENV-W1` | v0.1 の判定 (基準機) | Windows 11 Pro 64 ビット | 12 コア級 | 約 64 GB | 内蔵 NVMe SSD (計測データはここに置く) | Windows Terminal 1.24 系 | PowerShell 7.6 系 | サードパーティ製が常駐、Defender のリアルタイム保護は無効 | <記入: `rustc --version`> |

## 計測のたびに確かめて、`summary.md` の備考に書くこと

- [ ] 電源に接続している (電源プランは「高パフォーマンス」または同等)。
- [ ] リポジトリが外付け SSD にある場合、計測データ (`xtask gen-corpus` の出力) と一時ファイルは **内蔵 SSD** に置いている (`TEMP` も内蔵 SSD)。
- [ ] ウイルス対策の条件が上の表のとおり (起動の BM-101b / 102b の判定の条件)。変えて測ったときは別の行に参考値として書く。
- [ ] 他に重いプロセス (ビルド・同期ソフト) を止めている。
- [ ] ウォームキャッシュ (同じ計測を 1 回流してから測る。`xtask bench` の最初のウォームアップが兼ねる)。
- [ ] `cargo build --release` のビルドで測っている (`xtask bench` が自動でそうする)。
- [ ] 測ったコミットが「ゲートを判定する版上げ後の `develop` の先頭」である。

## 手順

```powershell
# 1. 計測データ (内蔵 SSD の作業ディレクトリに作る)
cargo xtask gen-corpus --seed 42 --out <内蔵 SSD の作業ディレクトリ>

# 2. 基準機の記録 (1,000 回。30 分ほどかかる)
cargo xtask bench --env ENV-W1 --out docs/perf/<版>

# 3. docs/perf/<版>/summary.md を読み、判定を決める。「不合格」と「参考」の扱いを release-checklist.md の「性能」の行に書く
```

`--quick` は動作確認用で、記録には使えない (`summary.md` に明記される)。
