## 所見 (2026-11-04、手で追記)

- **計測の条件**: exe (`CARGO_TARGET_DIR`) は内蔵 SSD の NTFS の上に置いた (09 §5.3 (e))。AC 電源で、電源モードは「最適なパフォーマンス」(`docs/perf/environments.md` の「高パフォーマンスまたは同等」)。計測中はブラウザなどの重いアプリを閉じた。
- **1 回目の計測を記録にしなかった理由**: 同じ判定コミットで 1 回目を測ったときは、電源モードが既定 (省電力寄り) のままで、ブラウザが動いていた (`environments.md` の確認項目を満たしていなかった)。そのため全体がほぼ 2 倍遅くなり、BM-101b・BM-103b・BM-103b-clip60・BM-103b-clip100 の 4 行が目標の境目を超えた。条件を直して測り直した結果が上の表で、この 4 行は合格。
- **BM-101b (rc.1 の不合格は解消)**: p50 29.88 ms / p99 37.59 ms (目標 p50 40 / p99 80 ms)。rc.1 の p99 218.57 ms は計測の仕方によるもの (`docs/perf/0.2.0-rc.1/summary.md` の所見) で、`bm_pty` の修正 (#326) の後は目標内。
- **BM-103b-search (不合格、例外 1 件)**: p50 2.44 ms が目標 (2 ms) を超えた (p99 3.92 ms は目標 8 ms の内)。
  - 製品の劣化ではない。判定の後に、判定コミット (`6728fde`) と rc.1 (`ced9f04`) の `bm_pty --only 404 --runs 1000` を同じ機械で交互に 3 回ずつ測ると、p50 は 1.98 / 1.90 / 1.93 ms と 2.04 / 2.00 / 1.88 ms で差が無い (p99 は 2.79〜3.04 ms)。
  - この機械では rc.1 も p50 が目標の境目 (約 2 ms) にあり、余裕が無い。rc.1 の記録の 1.30 ms と上の表の 2.44 ms は、ばらつきの両端と見る。
  - 扱い (PO 判断、2026-11-04): 記録はこのまま残し、例外として v0.2.0 を出す。全件検索中のキー入力の処理を軽くして余裕を作るのは、v0.2.x 以降の課題とする (#334)。
- **前の版との比較**: BM-103b の p50 は 1.71 → 1.57 ms、p99 は 3.78 → 4.90 ms (目標内)。BM-205 (exe の大きさ) は 4,953,600 → 4,962,304 バイト。
