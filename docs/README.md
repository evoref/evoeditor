# evoeditor 仕様書 (docs/)

evoeditor は Rust 製のテキストエディタである (名称は確定。バイナリ名も `evoeditor`、[OQ-01](10-decisions.md#oq-01-正式名称とバイナリ名))。TUI 版を最小核 (v0.1。Windows 向け) から段階的にリリースしながら継続的に進化させ、1.0 以降に **ローカル LLM を一級市民とする** AI 支援を載せる。TUI と core は OSS (Apache-2.0) で公開する。本ディレクトリはその **仕様書群** であり、仕様書駆動 ([ADR-0001](10-decisions.md#adr-0001-仕様書駆動での開発)) で開発する。

### 1.1 主な決定

主な決定の索引。各決定の内容・根拠・状態は 10 の該当 ADR・OQ が正。

- **開発の進め方**: 仕様書駆動 (ADR-0001。版の範囲ごとに確定してから実装する、OQ-115)・実装着手ゲート G1a / G1b / G1c (OQ-115)・段階リリース (ADR-0028)・AI 連携に適した開発構成 (ADR-0033)・ブランチ (OQ-167)・public のまま開発 (OQ-168)。
- **構造**: core / frontend の分離 (ADR-0002)。G1a に必須の ADR (ADR-0003 / 0006〜0012 / 0017 / 0020〜0022 / 0025 / 0030〜0032) は確定、ADR-0004 / 0005 / 0016 / 0023 / 0026 は条件付き確定。
- **v0.1 の範囲**: 版の正本は 01。先行投資の縮小 (ADR-0039) と最小核 ([ADR-0042](10-decisions.md#adr-0042-v01-の最小核-案-lwindows-のみの出荷日本語のみの-ui)。外した項目は [10](10-decisions.md#v01-の範囲から外した項目))。Windows のみ出荷・macOS / Linux は v0.2 (OQ-15)。スワップは v0.2 の最優先 (OQ-42)・線形 Undo (OQ-114)・未編集の上書き保存は書き込まない (OQ-116)・改行の保持 (OQ-04 / 51)・クリップボードは Win32 API (OQ-111)・巨大ファイル・長大行・桁 (OQ-05 / 31 / 32)・終了コードと保存の既定 (OQ-28 / 34 / 73)。
- **日本語**: Shift_JIS・EUC-JP・ISO-2022-JP の読み書き (OQ-03)・照合が成り立たない文字コードは読込のみ (OQ-162)・対応しない文字コード ([03 §8.9](03-core-design.md#89-対応しない文字コード))・v0.1 の UI 文言と利用者向け文書は日本語のみ (OQ-21 / 67)、英語は v0.2 (OQ-21)。
- **操作と表示**: モードレス CUA・チョードの 1 打目は時間切れにしない・主修飾 `mod` (OQ-02 / 26 / 29 / 30 / 38)。TrueColor 既定と色の段 (ADR-0027、OQ-27)。
- **性能**: 数値目標は 01 §3 (OQ-113)。基準機と最低環境 (OQ-23、§1.2)。
- **名称**: evoeditor、接頭辞 `eve-` / `.eve/` / `EVE_` (OQ-01)。
- **1.0**: TUI 完成 = v1.0 のリリース + 重大不具合ゼロ (OQ-151)。
- **ライセンス**: Apache-2.0 単独 (OQ-152 / 19)・寄稿は DCO (OQ-154)・依存は許可リスト (正本は [05 §17.1](05-platform.md#171-ライセンス運用-adr-0018-の具体化検査は-09)) に限り cargo-deny で検査する (ADR-0018、確定 (ユーザー回答、2026-10-20)。`deny.toml` は 05 §17.1 の許可リストで作る)・名称とロゴの使用方針 (OQ-01)・docs/ の公開と `main` の docs/ をリリースした版の仕様にする運用 (OQ-160 / 167 / 168)・公開 crate の外部の消費者 (ADR-0038、確定 (ユーザー回答))。
- **AI**: ローカル LLM を一級市民とする (ADR-0034 / 0036)・補完の送信先はループバックのみ (OQ-132 / 135)・外部エージェント連携 (OQ-11)。
- **更新**: エディタ内に更新機能を持たない (ADR-0040、[05 §18.10](05-platform.md#1810-更新の方針-adr-0040))・明示実行の更新確認 `--check-update` は採否が提案中 (ADR-0041)。

> **v0.1 の既知の制約**: Windows 11 のみ出荷、単一文書、正規表現の検索なし、ログオフ・シャットダウン時は未保存の内容が退避されないことがある、conhost の描画品質は best effort、コード署名なし、など。一覧は [01 §4.6](01-requirements.md#46-v01-の既知の制約-リリースノートとヘルプに明記する) (リリースノートと利用者向け README に載せる)。

### 1.2 対象 OS

v0.1 は **Windows のみ出荷する** (確定 (ユーザー回答)、[OQ-15](10-decisions.md#oq-15-対応-os端末の範囲))。macOS / Linux は **v0.2 で出荷する** (確定 (ユーザー回答))。出荷には実機確認の手段 (基準機の追加、OQ-23 (d)) の確保が前提で、確保できない OS は次の版に延期する (提案中)。開発と検証の環境は Windows のみで、実機で確かめられない OS は出荷しない。正本は [01 §4.6](01-requirements.md#46-v01-の既知の制約-リリースノートとヘルプに明記する)。

| OS | v0.1 | 内容 |
|---|---|---|
| Windows | **出荷する** | Windows 11 の Windows Terminal と conhost (conhost は描画品質が best effort)。Windows 10 は公式には対応しない ([05 §1.1](05-platform.md#11-osアーキテクチャターゲット-nfr-401--oq-15))。x86_64 のアーカイブ (zip + SHA256SUMS + minisign) と `cargo install --locked --git`。開発機で実機の動作確認と性能の判定を行う |

| Linux | **v0.1 では出荷しない** (v0.2 で出荷) | 同上。Must 端末は GNOME Terminal と tmux。v0.1 の間も CI で Linux CI の対象 crate (core 系 + `eve-host` + `eve-testkit`、[09 §6.4](09-testing-quality.md#64-テストマトリクス-os--アーキ)) のビルドとヘッドレスのテストを行い、移植性を守る |

- macOS / Linux を出荷する v0.2 で確認する項目は [08 §3.1](08-roadmap.md#31-v02-macos--linux-出荷時-の対象)。

6. **クリップボード**: `wl-copy` / `xclip` / `xsel` / WSL の `powershell.exe` と OSC 52 (FR-205、05 §8)。**実装 (2026-11-01)**: eve-platform の `clipboard_cmd` (検出と外部コマンドの起動)、Host の手段が無い理由の通知、eve-tui の Unix の `osc52_write`、bin の配線 (05 §8.1 の「Linux の実装」)。**訂正 (2026-11-01)**: WSL の copy は `clip.exe` ではなく `powershell.exe` の `Set-Clipboard` にした (`clip.exe` は BOM の扱いで化ける。WSL で実測、05 §8.2)。WSL (Windows Terminal) で Windows のクリップボードとの往復を確かめた。`wl-copy` / `xclip` / `xsel` は検出と起動の試験だけで、実機のデスクトップ環境での確認は未確認のまま (本節の末尾の決定)。
7. **CI と配布**: Linux CI の対象に eve-platform・eve-tui・bin を足し、e2e を Linux の pty でも回す。musl の静的版 (x86_64。aarch64 はクロスビルド) の tar.gz・`SHA256SUMS`・`release.yml`・`check-dist`。2 本に分ける: 7a = Linux の e2e、7b = musl の静的版の配布。**7a の実装 (2026-11-01)**: L5 の e2e を Linux の `openpty` でも回す (`ci.yml` の `e2e (linux)`。Unix のシグナルの試験を加えた、09 §3.6 の「Linux の実装」)。Linux CI の対象 crate は 5b で足し済み。
8. **一貫性の検査と受入**: LazyFS の夜間ジョブ (NFR-301、M10 から移した)、`no-network` を実 FS に替える、Unix の kill テスト、WSL での手動受入 (Windows Terminal + WSL、tmux。GNOME Terminal は WSLg で使えれば)、互換性マトリクス、利用者向け文書の Linux の導入・更新 (日本語・英語)。

**WSL で確かめられないもの** (既知の制約に残すか、利用者の協力で確かめる): 実機のデスクトップ環境 (GNOME / KDE の Wayland・X11) のクリップボードと IME (mozc) の候補窓、`TERM=linux` のコンソール。**決定 (ユーザー回答、2026-11-01)**: これらは **未確認の状態のままで先に進める** (v0.2 の互換性マトリクスと既知の制約に「未確認」と書く)。macOS は実機が無いので保留のまま。
