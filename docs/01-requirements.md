### 1.2 優先度 (MoSCoW)

- **Must**: その版の完了条件。欠けたらリリースしない。
- **Should**: 強く望む。期限が厳しければ次の版へ繰り越せる (繰り越しは [08-roadmap §7](08-roadmap.md#7-繰り越し記録) に記録)。
- **Could**: 余力があれば。
- **Won't (now)**: 当面やらない。[00 §3 非目標](00-overview.md#3-非目標-non-goals) 参照。

1 つの要件を段階的に満たす場合は「Must (v0.1: 範囲 A) / Should (v0.2: 範囲 B)」のように書く。

### 1.4 受入基準の書き方

各要件は「検証方法」で T (自動テスト) / B (ベンチマーク) / M (手動確認) / R (レビュー) のいずれかを示す。区分の定義 (実行者・頻度・記録) は [09 §2](09-testing-quality.md#2-検証区分-t--b--m--r-の定義)、詳細手順は 09-testing-quality で定義する。

**受入基準**: 要件文は 1 行に留め、Must 要件の **判定可能な受入基準 (AC)** は [§5](#5-受入基準-must-要件) に置く。AC は `AC-<要件ID>-<n>` で識別し、09 のトレーサビリティはテストの存在だけでなく AC との対応も検査する。リリースゲートは「その版の Must の AC がすべて合格」。

## 4. MVP (v0.1) の範囲と段階リリース

### 4.1 v0.1 の定義

> **v0.1「最小核」**: Windows 11 の Windows Terminal と conhost で、**1 つのテキストファイル** を開き、日本語 (IME・全角・絵文字) で編集し、文字列で検索して、元の文字コード (UTF-8・UTF-8 BOM 付き・UTF-16 BOM 付き・Shift_JIS・EUC-JP・ISO-2022-JP)・改行コードのまま原子的に保存できる。保存すると文字が化ける場合は書き込まずに知らせる。異常終了しても未保存の内容は退避される。TrueColor で表示し、起動はプロセス内で 8 ms 以下、入力の処理は 2 ms 以下 (p50)。UI の文言は日本語。配布するのは Windows 版だけで、Windows 10 と macOS / Linux は v0.1 では対象にしない (core は OS 非依存を保ち、CI で Linux のビルドとテストを続ける)。
>
> この範囲は確定 (ユーザー回答、[ADR-0042](10-decisions.md#adr-0042-v01-の最小核-案-lwindows-のみの出荷日本語のみの-ui))。macOS / Linux の出荷と英語 UI の同梱は v0.2 (確定 (ユーザー回答)、§4.3)。

v0.1 に残すのは、次の 3 軸のどれかに **直接** 必要で、欠けると利用者がデータを失うか、日本語が使えないか、遅いと感じるものに限る。「便利」「なくても代わりの手段がある」ものは v0.2 以降に回す ([ADR-0028](10-decisions.md#adr-0028-リリース最優先の段階リリース))。

| 軸 | 意味 | 外すと何が起きるか |
|---|---|---|
| S 安全 | 開く・編集・保存でデータを壊さない・失わない | 利用者のファイルを壊す / 未保存の内容を失う |
| J 日本語 | 日本語のテキストを正しく表示・入力・保存できる | 文字化け、全角の崩れ、IME が使えない |
| F 速い | 起動・入力・大きなファイルで待たされない | 「重い」と言われ、目標と矛盾する |
| 基盤 | 上の 3 つを支える構造で、後から入れると公開面を壊すもの | 後で作り直しが必要になる |

### 4.4 v0.1 で残す拡張点 (先行投資)

後の版で実装する機能について、**v0.1 の設計が後からの追加を妨げてはならない**。原則は「公開面は v0.1 で形を決め、内部構造は v0.1 では最小にする」(ADR-0028)。「残すもの」は、最初の利用者が v0.1 にいなければ **型・ID・書式の予約** に留め、実装は最初の利用者と同時にする ([ADR-0039](10-decisions.md#adr-0039-v01-の範囲の整合と先行投資の縮小))。拡張点の定義は 02。

### 4.6 v0.1 の既知の制約 (リリースノートとヘルプに明記する)

v0.1 にはヘルプ画面が無い (FR-514) ので、「ヘルプ」はリリースノートと README の「既知の制約」節を指す (ヘルプ画面を入れる v0.2 からは画面にも載せる)。v0.1 の UI は日本語のみなので、これらの利用者向け文書も日本語を正とする (§4.2。英語版は v0.2)。

| 制約 | 内容 | 扱い |
|---|---|---|
| SIGKILL・OOM・電源断での未保存内容 | v0.1 の緊急退避はこれらの経路では動かない。スワップは v0.2 | リスク受容 (PO 判断、[OQ-42](10-decisions.md#oq-42-v01-の非パニック異常終了への備え))。原子的保存があるのでディスク上のファイルは壊れない。巨大ファイルを開く前の警告と `try_reserve` で OOM の経路を減らす |
| ISO-2022-JP の半角カナ | ISO-2022-JP では半角カナを表現できない (エンコーダが全角に変える) ため、保存前に表現不能として止め、「置換して保存」(半角カナは全角カナに、JIS 系の互換文字 (U+301C 等) は CP932 の文字 (U+FF5E 等) に、他の表現不能文字は `?` に。置換前に一覧を示す。03 §8.6) 等を選ばせる | 確定 (ユーザー回答)、OQ-03 (互換文字の置換は OQ-208) |
| 不正バイトを含む文書は読み取り専用 | 「文字コードを指定して開き直す」で回復 | v0.3 で編集・保存 |
| 読み取り専用のファイルは編集できない | 読み取り専用属性のファイルと `--readonly` で開いた文書は編集できない (理由を示して拒否する)。書込権限の無いファイルは保存に失敗した時点で読み取り専用に切り替わる。編集するには「名前を付けて保存」で別のファイルにする (保存先が書き込めれば編集できる) か、エディタの外で属性を外してから再読込 (`file.reload`。属性による理由は読み直したファイルの属性で付け直す、03 §9.5) する | v0.2 で解除のコマンドと「読み取り専用を解除して保存」(FR-116) |
| 区分 B の文字のバイト表現 | 補助漢字・重複符号化を含む文書を編集して元の文字コードで保存すると、一部のバイト表現が変わる (保存前に確認が出る) | v0.3 で保持方式 |
| 単一文書 | 同時に開ける文書は 1 つ。別のファイルを開く・新規バッファを作ると今の文書を置き換える (dirty なら保存 / 破棄 / キャンセルの確認が出る)。コマンドラインのパスは 1 つまで (2 つ以上は「未対応」と表示して終了コード 2)。複数の文書は端末のタブ・ウィンドウで別々に起動して扱う | v0.2 で複数文書 (FR-103) |
| 長大行は読み取り専用 | 1 MiB を超える行を含む文書は読み取り専用で開き、その行は先頭 64 KiB まで表示する。編集するには他のツールで行を分ける | v0.2 で編集 (char 近似モード。M9d で実装、03 §11.5.1)、v0.3 で書記素単位の正確さ |
| 正規表現の検索なし | 検索は文字列 (リテラル) と大文字小文字の区別だけ (`regex` は大文字小文字を区別しないリテラル検索の内部経路で使うが、利用者が正規表現を書く経路は無い。確定 (ユーザー回答))。置換はリテラルの「すべて置換」だけで、1 件ずつ確認しながら置換する手段は無い (すべて置換は 1 回の元に戻すで戻せる) | v0.2 で行単位の正規表現と 1 件ずつの置換、v0.3 で複数行 |
| 外部の変更は保存時まで知らされない | 開いた後に他のプログラムがファイルを変えても、保存するまで知らせない (保存時は「上書き / 別名で保存 / 中止」の確認が出る)。読み直すには再読込 (`file.reload`) を使う | v0.2 でフォーカス復帰時の確認、v0.4 でファイル監視 |

## 5. 受入基準 (Must 要件)

各 Must 要件の **判定可能な受入基準 (AC)**。数値・端末・コーパスは 09 で具体化してよいが、合否の意味を変えてはならない。「暫定」は P0 の結果で確定する。v0.2 以降の要件の AC は概要であり、該当する版の着手前 ([08](08-roadmap.md)) に詳細化する。共通の前提: 対象 OS = NFR-401 (v0.1 は Windows 11 のみ)、対象端末 = NFR-402 (v0.1 は Windows 11 の Windows Terminal と conhost)、コーパス = 09 §4。macOS / Linux に固有の AC (Unix のモード・シグナル・非 UTF-8 パス等) は、macOS / Linux を出荷する版で適用する。
