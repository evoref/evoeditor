# 互換性・手動受入の手順書 (v0.1)

リリースの前に、基準機 (Windows 11) の **Windows Terminal** と **conhost** で、この手順書の項目を実機で確かめる (docs/09 §3.7 / §3.8、05 §9.4、08 §2.2 のリリースゲート (5))。結果は版ごとに `docs/compat/<版>/windows-<端末>.md` (雛形: [`_template/windows-terminal.md`](_template/windows-terminal.md)) に書き、手順 H と I は `docs/compat/<版>/acceptance.md` に書く。タグの前に `develop` にコミットする。

**書かないもの**: 基準機の固有情報 (機種名・型番・OS のビルド番号・ウイルス対策ソフトの製品名・ユーザー名を含むパス)。Windows と端末は **版 (例: Windows 11 24H2 級、Windows Terminal 1.24 系)** までにする (docs/11 §9.7)。

## 準備

1. 配布物の exe で確かめる。`cargo xtask dist` で作った zip を展開した `evoeditor.exe` を使う (開発ビルドではない)。
2. 設定ファイルが無い状態 (`EVE_CONFIG_DIR` を空のフォルダに向ける) と、`config.example.toml` を写した状態の両方で起動できることを、最初に 1 回ずつ確かめる。
3. 端末ごとに新しいウィンドウで始める。確かめる端末: **Windows Terminal** (判定の対象) と **conhost** (機能の確認。描画の品質は best effort)。
4. 日本語入力は **Microsoft IME** と **Google 日本語入力** のそれぞれで確かめる (どちらも入っていなければ、入れてから)。
5. 手順の中で使うファイルは、リポジトリの外の作業フォルダに作る (内蔵 SSD)。個人の文書は使わない。

各項目の結果は **○** (期待どおり)・**△** (動くが気になる点あり。内容を備考に)・**×** (期待どおりでない。内容と再現手順を備考に) のいずれかで書く。× と △ は Issue にし、番号を備考に書く。× が 1 つでもあれば、原因を調べてからゲートを判定する。

## A. 起動と終了

| # | 手順 | 期待 |
|---|---|---|
| A1 | `evoeditor` を引数なしで起動する | 無題の文書の画面が出る。ステータスバーに `無題-1`、ヒントバーが出る |
| A2 | `Ctrl+Q` で終了する | 終了し、端末が元の状態に戻る (代替スクリーンを抜ける・カーソルが出る・色が戻る) |
| A3 | `evoeditor --version` と `evoeditor --help` | 版と使い方が出る。`--version` は配布 zip の版と一致する |
| A4 | 存在しないパスを指定して起動し、保存する | 新規ファイルとして保存できる |
| A5 | 日本語のファイル名 (`日本語.txt`) の UTF-8 のファイルを引数で開く | 本文が崩れずに出る |

## B. 日本語入力 (IME)

編集面・コマンドパレット (`F1`)・入力プロンプト (`Ctrl+G` の行番号など)・検索バー (`Ctrl+F`) の入力欄のそれぞれで確かめる。

| # | 手順 | 期待 |
|---|---|---|
| B1 | IME をオンにして 3 文を入力する (変換・確定) | 変換中の文字が編集位置に出る。確定した文字列が正しく入る |
| B2 | 変換中に `Esc` で取り消す | 変換が取り消され、確定前の文字は入らない |
| B3 | 変換候補のウィンドウの位置 | カーソルの近くに出る (画面の端に飛ばない) |
| B4 | 長い行 (画面幅より長い) の末尾で入力する | 候補の位置がずれない。画面が崩れない |
| B5 | 全角文字・絵文字・半角カナを入れて、矢印キーと Backspace で動かす | カーソルが文字の境界で動く。表示が崩れない |

## C. 表示とキー

| # | 手順 | 期待 |
|---|---|---|
| C1 | ウィンドウの大きさを変える (大きく・小さく・極端に小さく) | 再描画され、崩れない。極端に小さいときは落ちない |
| C2 | `Ctrl+Shift` を含むキー (`Ctrl+Shift+Z` など) と `Ctrl+Z` | 区別されて動く (元に戻す / やり直し) |

| C4 | 色の表示 (検索一致・選択・ダイアログ) | 区別できる。conhost でも記号や属性で区別できる |
| C5 | 色の段階を固定して見る (FR-513 AC-4): `config.toml` の `[theme]` の `color_mode` を `"truecolor"` / `"256"` / `"16"` / `"none"` に 1 つずつ変えて起動する。さらに `color_mode = "auto"` のまま環境変数 `NO_COLOR=1` で起動する (PowerShell: `$env:NO_COLOR = "1"`)。それぞれの段で、複数の行の文書に `Ctrl+F` で語を検索し、範囲選択し、`F1` でパレット、未保存で `Ctrl+Q` で確認ダイアログ、存在しないフォルダのパスを `Ctrl+O` で開いて警告を出す | どの段でも、**選択範囲・検索の一致と現在の一致・ステータスバー・メッセージの種類 (情報 / 警告 / エラー) を見分けられる**。256 / 16 色は truecolor からの自動近似で、区別は記号・属性 (反転・下線・太字) で保たれる。`none` と `NO_COLOR` では色が一切出ず、属性と記号だけで区別できる |

## L. Linux (v0.2): WSL の Windows Terminal と tmux (記録は `linux-wsl.md`)

v0.2 の Linux の受入は、開発 PC の **WSL2 (Ubuntu)** を **Windows Terminal** で開いて行う (docs/README §3.9 の M7。実機のデスクトップ環境 (GNOME / KDE) は未確認のまま出荷する決定、05 §9.4)。雛形は [`_template/linux-wsl.md`](_template/linux-wsl.md)。

**準備**: Linux の musl 静的版の tar.gz (`cargo xtask dist --target x86_64-unknown-linux-musl` で作ったもの、またはリリースの候補) を使う (開発ビルドではない)。手順 L1 で README の Linux の手順どおりに入れたものを、以降の項目で使う。作業のファイルは WSL の中 (`~` の下) に作る。

**自動の部分**: 最初に WSL の中で `cargo xtask accept-linux` を実行する (候補の tar.gz があれば `--archive <tar.gz>`。隣に `SHA256SUMS` を置く)。L1 と、A1〜A5・C1・C2・C5・D1・D3・D4・D6・E1〜E3・F1〜F6・G1〜G3・L2〜L5・L7・L8 の端末の中の動作を tmux で確かめ、`target/accept-linux/result.md` に結果を書く (L4 は Windows のクリップボードを一時的に書き換え、終わると元に戻す)。○ の項目は記録に「自動」と書いて写してよい。× は Issue にする。**手で行うのは** 次の項目だけ: B1〜B5・L6 (日本語入力)、C2 と L8 の Windows Terminal から押した `Ctrl+Shift` のキー、C3、C4 (色の見た目)、D2 (右クリックの貼り付け)、D5 (端末の範囲選択)、L2 の Windows Terminal のタブを閉じる操作、L5 の `Ctrl+Shift+V` と右クリック、L7 の推奨設定の tmux を Windows Terminal で開いた見た目。

**A〜G**: 上の A〜G を WSL の中で同じ手順で行う。読み替え: 設定は `~/.config/evoeditor/config.toml`、PowerShell の例は sh に読み替える (`NO_COLOR=1 evoeditor`)、D の「他のアプリ」は Windows のアプリ (メモ帳など)、G のコーパスは WSL の中で作る。

| # | 手順 | 期待 |
|---|---|---|
| L1 | README の「インストール」の Linux の手順どおりに、署名とハッシュを検証し (`sha256sum -c SHA256SUMS --ignore-missing`)、`~/.local/opt/evoeditor` に展開し、`~/.local/bin` にリンクを置き、ログインし直して `evoeditor --version` を実行する | 手順どおりにでき、版が出る |
| L2 | 編集して未保存のまま、Windows Terminal の WSL のタブを閉じる (SIGHUP)。もう一度起動する | 未保存の内容が `~/.local/state/evoeditor/recovery/<日時>-<pid>/` に退避され、起動時に案内される |
| L3 | `Ctrl+K Z` でシェルに戻り、`fg` で戻る。戻る前に端末の大きさを変えておく | シェルに戻るときに端末が元に戻る。`fg` で代替スクリーンに戻り、今の大きさで描き直される |
| L4 | エディタで選択して `Ctrl+C` し、Windows のアプリに貼る。Windows のアプリでコピーしてエディタに `Ctrl+V` で貼る (日本語・改行を含む) | 内容が一致する (WSL では `powershell.exe` 経由。1 回目は少し待つことがある) |
| L5 | 端末の貼り付け (`Ctrl+Shift+V` か右クリック) で、D1 の 100 行と D3 の `paste-injection.txt` を貼る | D1・D3 と同じ (Linux はブラケットペーストで届く) |
| L6 | B1〜B4 を WSL の中で行う (Microsoft IME と Google 日本語入力) | B1〜B4 と同じ |
| L7 | tmux (README の推奨設定あり) の中で A1・A2・C1・C2・F1 を行い、未保存のまま `tmux kill-session` する | 動作は tmux の外と同じ。kill-session で L2 と同じく退避される |
| L8 | tmux の推奨設定なし (`tmux -f /dev/null`) で `Esc` と `Ctrl+Shift` を含むキーを押す | 動く (`Esc` の反応が遅いのは tmux の `escape-time` のため。README の既知の制約のとおり) |

## N. 標準入力 (v0.4 の M25。記録は `stdin.md`)

`cmd | evoeditor -` で標準入力を開く手の確認 (05 §9.4 の「標準入力の手での確認」、03 §9.2.2、07 §18.5)。雛形は [`_template/stdin.md`](_template/stdin.md)。

**確かめる環境**: Windows Terminal (PowerShell 7 と cmd)・conhost・VS Code の統合端末・mintty (Git Bash)・Windows PowerShell 5.1 のパイプ・WSL からの interop (WSL の中から `cmd.exe /c "… | evoeditor.exe -"` と、WSL の側のパイプ `cat … | evoeditor -`)・tmux の中 (WSL)・`ssh -t` 越し (Linux のホストへ)。環境に当てはまらない項目 (Windows の N3・N5) は「—」と書く。

**準備**: 手順 G1 の `large-100mb` と、日本語・CRLF を含む小さな UTF-8 のファイル (数 KB。以下 `small.txt`) を作業フォルダに置く。

| # | 手順 | 期待 |
|---|---|---|
| N1 | (a) 閉じるパイプ: `small.txt` を `type small.txt \| evoeditor -` (cmd)・`Get-Content -Raw small.txt \| evoeditor -` (PowerShell)・`cat small.txt \| evoeditor -` (sh) で渡す。続けて `large-100mb` を同じように渡し、読込中に矢印キーを押す。読み終えたら `Ctrl+Q` | `type` / `cat` では、待ちの行 (「標準入力を待っています (Ctrl+C で中止)」) は終了の後の画面に残らない。読み終えた内容が無題の文書で開き、`small.txt` と一致する (日本語・改行コード)。100 MB では読込中にステータスバーに `[読込中 12.3 MiB]` の形で読んだ量が出て、入力に応答する。読み終えた文書は変更ありで、`Ctrl+Q` で未保存の確認が出る。Windows PowerShell 5.1 のパイプでは非 ASCII が `?` になる (既知の制約。ヘルプの注意のとおり) |
| N2 | (b) 閉じないパイプ: `ping -t localhost \| evoeditor -` (Windows)・`tail -f small.txt \| evoeditor -` (sh) で起動し、数秒後に `Esc` を押して「ここまでで開く」(`O`) を選ぶ。別の回で、`Esc` の確認で「読み続ける」(`Esc`) を選ぶ。もう一度起動し、読込中に `Ctrl+Q` を押す | `Esc` で確認「標準入力の読込 / 読むのをやめると書き手が止まり、続きは読めません」が出る。「ここまでで開く」で、読んだ分が読み取り専用 (途中までしか読んでいない内容) で開き、「標準入力を読むのをやめ、ここまで ({size}) を読み取り専用で開きました」が出る。「読み続ける」では読込が続く。`Ctrl+Q` では「標準入力を読み込み中です ({size})」の確認 (ここまでで開く / 破棄 / キャンセル) が出る。**書き手の止まり方を記録する**: Unix の `tail -f` は SIGPIPE で終わる。Windows の `ping -t` は止まらず、evoeditor の終了の後に `Ctrl+C` で止める (07 §18.5) |
| N3 | (c) 書き手がパスワードを尋ねる (Unix): `sudo -k` の後に `sudo cat small.txt \| evoeditor -` でパスワードを入れる。終了の後に何か打ち込む | パスワードの入力の間は evoeditor の画面にならず、「標準入力を待っています (Ctrl+C で中止)」が出る (端末の初期化は最初のデータまで待つ。OQ-219 の 9)。入力の後に画面が出て崩れない (崩れたら `ui.redraw` で直る)。終了の後、打ち込んだ文字がエコーされる (`stty -a` に `echo`) |
| N4 | (d) 端末の判定: コンソール (Windows Terminal・conhost) と mintty の擬似端末で `evoeditor -` を直接起動する。`evoeditor - < NUL` (cmd) と `evoeditor - < /dev/null` (sh) で起動する | 端末からは、空の文書と「標準入力が端末のため、読まずに空の文書を開きました」。`NUL` / `/dev/null` からは、空の文書でメッセージなし。どちらも変更なしで、`Ctrl+Q` で確認なしに終わる |
| N5 | (e) 読込中のサスペンド (Unix): `tail -f small.txt \| evoeditor -` の読込中に `Ctrl+K Z`、シェルで `jobs`、`fg` | シェルに戻るときに端末が元に戻り、パイプラインごと止まっている (`jobs` に `tail` と `evoeditor` が 1 つのジョブで出る)。`fg` で戻り、画面が描き直され、読込が続く |

## P. 高コントラストテーマ (v0.4 の M26。記録は `high-contrast.md`)

組込みテーマ `high-contrast-dark` / `high-contrast-light` を端末で目で確かめる (08 §2.5 の M26 の (4)、09 §8.2 の互換の行、07 §8.7、04 §12.5、NFR-604)。雛形は [`_template/high-contrast.md`](_template/high-contrast.md)。値 (07 §8.7 の表) は、この確認で見直してよい (基準は満たしたまま、表と実装を同じ PR で直す)。

**確かめる環境**: Windows Terminal と conhost。テーマは `high-contrast-dark` と `high-contrast-light` の両方。色の段は truecolor・256・16 (conhost で truecolor・256 が描けない場合は、描けた段だけを確かめ、記録に「—」と書く)。

**テーマの選び方**: 設定ファイルは変えず、起動のたびに `--set` で渡す。`evoeditor --set theme.name=high-contrast-dark <ファイル>` (明るい方は `high-contrast-light`)。`theme.background` は `"auto"` のまま (設定ファイルが無い状態 (`EVE_CONFIG_DIR` を空のフォルダに向ける) で行う)。

**色の段の切り替え**: `--set theme.color_mode=truecolor` / `256` / `16` を足す (例 `evoeditor --set theme.name=high-contrast-dark --set theme.color_mode=256 sample.txt`)。`color_mode` は起動時に決まるので、段を替えるたびに起動し直す。段の組み合わせは、テーマ 2 つ × 3 段 = 6 通りを端末ごとに回す。無色の段 (`--set theme.color_mode=none`) は C5 で確かめ済みなので、ここでは加えない。

**準備**: 作業フォルダに次を作る (個人の文書は使わない)。
- `sample.txt`: 50 行ほど。語「検索」を 5 か所以上、英字の「Search」を数か所含む。全角スペース・タブ・日本語を含む。
- `ctrl.txt`: 制御文字 (例 `\x01`) と不正バイト (UTF-8 として不正な 1 バイト) を含む短い文書 (不正バイトは、`[byte[]]` を `Set-Content -AsByteStream` で書くなどして作る)。
- 長い行 (200 文字以上) を含む行を `sample.txt` に 1 行足しておく (横スクロールの印 `‹` `›` を見るため)。

**1 通りごとの手順**: 下の P1〜P9 を、6 通り (テーマ × 段) × 2 端末で行う。時間を短くするため、P4・P5・P6・P7 は truecolor の段で全部を行い、256 と 16 の段では「期待」の見分けだけを見てよい (見分けられない箇所が出たら、その段でも全項目を行う)。

| # | 手順 | 期待 |
|---|---|---|
| P1 | 通常画面: `sample.txt` を開く。ガターの行番号・現在行の行番号・文書末尾より後の `~`・長い行の横スクロール (`End` で行末へ) の `‹` `›`・全角スペースとタブの可視化 (出ないときは `--set view.show_whitespace=all` を足して起動し直す。07 §5.3) を見る | 画面全体が、暗いテーマは黒の背景に白の文字、明るいテーマは白の背景に黒の文字で塗られ、端末の背景色が余白に残らない。本文が読める。行番号・`~`・横スクロールの印・空白の記号は、本文より少し淡い灰色で、本文と見分けられる (読める濃さ。見えなくならない)。現在行に帯は付かず、現在行の行番号だけが太字 (16 の段の暗いテーマは下線) になる。16 の段では、端末のパレット次第で色が変わる (コントラストは目安) |
